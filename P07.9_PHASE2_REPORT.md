## 2. Architecture Before

Prior to Phase 2:
- All skills were treated as instantaneous, one-frame executions regardless of configuration.
- `SkillDefinitionSO` had no `CastTime` property.
- `SkillCastState` existed as a foundation model from Phase 1, but was not integrated into `SkillExecutor`.
- `SkillExecutor.ExecuteSkill` executed validation, consumed Rage, invoked `EffectResolver`, and started cooldown all within a single synchronous method call.

---

## 3. Architecture After

After Phase 2:
- `SkillDefinitionSO` supports `CastTime` (default `0f`, ensuring 100% backward compatibility with existing skills).
- `SkillExecutor` remains the **sole execution authority**.
- When `CastTime <= 0f`: identical synchronous execution path is preserved (1 frame, immediate damage, rage, and cooldown).
- When `CastTime > 0f`:
  1. `SkillExecutionValidator.Validate(request)` validates preconditions.
  2. Rage is consumed **at Cast Start** (per P07.9-D02).
  3. `source.CastState.StartCast(request, request.Skill.CastTime)` transitions to `Casting`.
  4. Cooldown is **not** started at Cast Start (remains 0).
  5. Effects are **not** executed at Cast Start.
  6. Deterministic `Tick(deltaTime)` advances elapsed time.
  7. When `ElapsedTime >= CastDuration`, `SkillCastState` marks completion and delegates to `SkillExecutor.ExecuteCastComplete(castState)`.
  8. `SkillExecutor` executes effects via `EffectResolver`, triggers cooldown via `CooldownManager`, and fires `OnSkillExecutionSucceeded`.
  9. Strict guard ensures Cast Complete executes **exactly once**. Subsequent ticks do not re-execute effects.

---

## 4. Cast Execution Flow

```
[CastTime > 0 Skill Requested]
  │
  ├── 1. SkillExecutionValidator.Validate(request)
  │      └── Pre-cast validation passes
  │
  ├── 2. RageComponent.ConsumeRage(rageCost)  <-- Consumed ONCE at Cast Start (P07.9-D02)
  │
  ├── 3. source.CastState.StartCast(...)      <-- CurrentPhase = Casting, IsActive = true
  │      └── Cooldown is NOT started
  │      └── Effects are NOT executed
  │
  ├── 4. Deterministic progression: Tick(dt) ... Tick(dt)
  │      └── ElapsedTime advances, RemainingTime decreases (clamped >= 0)
  │      └── Target HP remains unchanged during casting
  │      └── Rage is NOT consumed again
  │
  └── 5. Cast Complete (ElapsedTime >= CastDuration):
         ├── State transitions to Recovery (hasCompleted = true)
         ├── Handed back to SkillExecutor.ExecuteCastComplete()
         ├── EffectResolver.Instance.ProcessEffects()
         │     └── DamageCalculator -> HealthComponent.TakeDamage() (Shield interception)
         ├── CooldownManager.TriggerCooldown()  <-- Cooldown begins AFTER completion (P07.9-D03)
         └── EventBus.RaiseSkillExecutionSucceeded()
```

## 5. Instant Skill Compatibility

- `SkillDefinitionSO.CastTime` defaults to `0f`.
- `SkillDefinitionSO.IsInstant` returns `true` when `CastTime <= 0f`.
- All existing skills (Normal Attacks, Mind Method Skills) execute synchronously with 0 frame delay.
- Verified in TEST 01: Instant skills execute immediately in one frame and deal damage synchronously.

---

## 6. Rage Behavior

- **Cast-Time Skills**: Rage is consumed exactly once at **Cast Start** (TEST 08).
- **No Double Consumption**: Rage is never consumed again during `Tick` progression or at Cast Complete (TEST 09).
- **Validation Failure**: If validation fails prior to cast start, no Rage is consumed.
- **Instant Skills**: Rage is consumed during synchronous execution as before.
- **No Duplicate Storage**: `SkillCastState` contains no Rage fields or duplicate managers (TEST 18).

---

## 7. Cooldown Behavior

- **Cast-Time Skills**: Cooldown does **not** start when the cast begins (TEST 10).
- **Post-Completion Timing**: Cooldown starts only after successful Cast Complete (TEST 11).
- **Instant Skills**: Cooldown starts immediately upon successful execution as before.
- **No Duplicate Storage**: `SkillCastState` contains no cooldown fields or duplicate authority (TEST 19).

---

## 8. Time Provider / Determinism

- Driven deterministically via `SkillCastState.Tick(float deltaTime)` and `Entity.TickActiveCast(float deltaTime)`.
- No Unity coroutines (`StartCoroutine`, `WaitForSeconds`).
- No async/await in core state machine.
- No dependence on Unity Animator or Animation Events.
- Deterministic progress verified across partial ticks in TEST 03 and TEST 04.

---

## 9. Target Handling

- `ActiveRequest.Target` is preserved throughout the casting lifecycle.
- Target receives damage through the standard pipeline only upon Cast Complete.
- No parallel targeting system or alternative target resolution was introduced.
