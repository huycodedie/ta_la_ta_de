## 4. Channel Lifecycle Design
- **Status:** PASS
- For `IsChannel == true`, the lifecycle follows:
  ```
  Validate
      ↓
  Consume Rage at Cast Start (once)
      ↓
  Start Channel (SkillCastPhase.Channeling or Casting if CastTime > 0)
      ↓
  Runtime Entity.Update() / Manual TickActiveCast()
      ↓
  Accumulated Elapsed Time reaches scheduled boundary (k * ChannelTickInterval)
      ↓
  Execute Periodic Effects via EffectResolver & DamageCalculator
      ↓
  Channel Duration Reached (ElapsedChannelTime >= ChannelDuration)
      ↓
  Finalize Channel (Set Recovery phase, prevent double execution)
      ↓
  Trigger Cooldown
      ↓
  Raise EventBus.OnSkillExecutionSucceeded
  ```
- Rage is consumed once at Cast Start; 0 Rage consumed per tick; no Rage refund on completion.
- Cooldown begins only after successful channel completion.

---

## 5. Tick Boundary Decision
- **Status:** PASS
- **Decision:** Ticks occur at integer multiples of `ChannelTickInterval`: `t_k = k * ChannelTickInterval` for `k = 1, 2, ...` where `t_k <= ChannelDuration`.
- **Large Delta Handling:** In `SkillCastState.Tick(float deltaTime)`, accumulated elapsed time is tracked. A `while` loop checks scheduled tick boundaries sequentially. If a single large `deltaTime` crosses multiple boundaries, all crossed ticks execute deterministically in sequence without loss.
- No periodic effect occurs at time 0 (`ElapsedChannelTime = 0`).

---

## 6. Final Tick / Duration Boundary Decision
- **Status:** PASS
- **Decision:** Ticks strictly execute if their scheduled boundary `k * ChannelTickInterval <= ChannelDuration` is reached.
- If `k * ChannelTickInterval == ChannelDuration`, that scheduled tick executes upon reaching that boundary before completion.
- If `ChannelDuration` is not an exact multiple of `ChannelTickInterval` (e.g. duration 1.2s, interval 0.5s), no artificial final tick is forced at 1.2s. Exactly 2 ticks (at 0.5s and 1.0s) execute.
- This adheres strictly to the rule: tick count emerges from `ChannelDuration + ChannelTickInterval + deterministic time progression`.

## 7. Target Handling Decision
- **Status:** PASS
- **Decision:** The original `request.Target` captured at skill start is preserved.
- Implemented `PreservedTargetResolver : ISkillTargetResolver` in `Assets/_Game/Combat/SkillTargetResolver.cs`.
- If `request.Target` dies mid-channel (`!request.Target.IsAlive`), `PreservedTargetResolver` resolves 0 targets for subsequent ticks.
- In accordance with `P07_9_DESIGN_CONTRACT_LOCKED.md` Section 11, dead targets cannot be damaged, no post-death damage occurs, and no silent retargeting is performed.

## 8. Entity Death Handling Decision
- **Status:** PASS
- **Decision:**
  1. In `Entity.Update()`: Guard `if (!IsAlive || !IsCasting) return;` prevents ticking dead entities.
  2. In `SkillCastState.Tick(deltaTime)`: Guard `if (ActiveRequest?.Source != null && !ActiveRequest.Source.IsAlive)` immediately calls `Interrupt(SkillCastInterruptSource.CasterDeath); return;`.
- A dead caster cannot complete, continue, or execute further periodic effects for an active channel.
