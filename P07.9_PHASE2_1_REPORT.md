## 2. Active Cast Re-entry Audit

### Investigation Target
We audited:
- `SkillExecutor.ExecuteSkill(SkillExecutionRequest request)`
- `SkillExecutionValidator.Validate(SkillExecutionRequest request, out SkillExecutionFailureReason failureReason, out string message)`
- `SkillCastState.StartCast(SkillExecutionRequest request)`
- `Entity.CastState`
- `Entity.TickActiveCast(float deltaTime)`

### Scenario Analyzed
1. Entity initiates Skill A with `CastTime > 0` (transitions into `SkillCastPhase.Casting`).
2. While Skill A is currently `IsActive == true` and `Phase == SkillCastPhase.Casting`, a second skill request for Skill B is issued (`SkillExecutor.ExecuteSkill(requestB)`).

### Answers to Audit Questions

1. **Is B rejected?**
   - **Before Phase 2.1:** **NO.** There was no validation check inspecting `source.IsCasting`.
   - **After Phase 2.1:** **YES.** B is rejected immediately.

2. **Where is it rejected?**
   - **Before Phase 2.1:** It was not rejected.
   - **After Phase 2.1:** Rejected in `SkillExecutionValidator.Validate` at Step 1.6 (`SourceAlreadyCasting`), and guarded in `SkillCastState.StartCast` via defense-in-depth.

3. **Is Rage consumed before rejection?**
   - **Before Phase 2.1:** Yes. Skill B passed validation, and `SkillExecutor.ExecuteSkill` consumed Skill B's Rage cost before calling `StartCast`.
   - **After Phase 2.1:** **NO.** Rejection occurs during validation (Step 1), strictly before Step 2 (Safe Rage Consumption). 0 Rage is deducted.

4. **Can B overwrite Skill A?**
   - **Before Phase 2.1:** **YES.** `SkillCastState.StartCast` unconditionally assigned `_currentRequest = request`, resetting timer to 0 and overwriting Skill A with Skill B.
   - **After Phase 2.1:** **NO.** Because B is rejected, `StartCast` is never invoked for B. Furthermore, `SkillCastState.StartCast` explicitly guards `if (IsActive) return false;`.

5. **Can B create a second active cast?**
   - **Before Phase 2.1:** No second instance was created because `Entity` maintains exactly one `CastState` reference, but B overwrote A.
   - **After Phase 2.1:** **NO.** Single `CastState` authority is preserved, and re-entry is blocked.

6. **Can Skill A still complete correctly?**
   - **Before Phase 2.1:** No, Skill A's state was destroyed by B's overwrite.
   - **After Phase 2.1:** **YES.** Skill A's cast state remains active, its elapsed time and remaining duration continue advancing upon subsequent ticks, and upon reaching completion, Skill A executes its effects normally.

7. **Can effects execute twice?**
   - **Before Phase 2.1:** If B was an instant skill (`CastTime == 0`), B's effects executed immediately while A was in progress, leading to invalid concurrent casting/effect states.
   - **After Phase 2.1:** **NO.** Skill A's effects execute exactly once upon completion; Skill B's effects never execute.

## 3. Actual Re-entry Behavior Before

Prior to Phase 2.1:
- `SkillExecutionValidator.Validate` checked null requests, dead source, skill definition, dead target, cooldown status, crowd control status (`CanUseSkill` / `CanUseUltimate`), rage requirements, and mind method affiliation.
- **Critical Gap:** It did **NOT** verify whether the source entity was already in the middle of casting (`source.IsCasting`).
- When a player or AI attempted to cast Skill B while Skill A was casting:
  1. Skill B passed validation.
  2. Skill B consumed Rage from `source.Rage`.
  3. If Skill B was instant (`CastTime == 0`), `SkillExecutor` executed Skill B's damage, effects, and cooldown immediately, while `source.CastState` was left in an undefined/desynced state.
  4. If Skill B had `CastTime > 0`, `SkillCastState.StartCast(requestB)` overwrote `_currentRequest` with B and reset `ElapsedTime` to 0, completely destroying Skill A's cast without triggering interruption, cancellation, or refunds.

## 4. Change Made

To enforce the invariant **ONE ENTITY -> AT MOST ONE ACTIVE CAST**, the minimal, surgical changes were applied:

1. **`SkillExecutionTypes.cs`**:
   - Added new enum value to `SkillExecutionFailureReason`:
     ```csharp
     SourceAlreadyCasting = 10
     ```

2. **`SkillExecutionValidator.cs`**:
   - Added Step 1.6 active cast check before Rage deduction and skill execution:
     ```csharp
     // 1.6 Source Already Casting Check (P07.9 Phase 2.1 Re-entry Guard)
     if (source.IsCasting)
     {
         failureReason = SkillExecutionFailureReason.SourceAlreadyCasting;
         message = $"Source entity '{source.EntityName}' is already casting.";
         return false;
     }
     ```

3. **`SkillCastState.cs`**:
   - Added defense-in-depth safety guard inside `StartCast`:
     ```csharp
     if (IsActive)
     {
         return false;
     }
     ```

No other gameplay rules, channels, cancels, refunds, or parallel authorities were introduced.

## 6. Actual Runtime Tick Call Chain

We audited the entire codebase to trace production call chains invoking:
```csharp
Entity.TickActiveCast(float deltaTime)
```

### Audit Findings:
1. **Search across repository**:
   - `Entity.TickActiveCast` is defined in `Assets/_Game/Entities/Entity.cs`:
     ```csharp
     public virtual void TickActiveCast(float deltaTime)
     {
         _castState?.Tick(deltaTime);
     }
     ```
2. **Current Invocation Locations**:
   - `Assets/_Game/Editor/Prototype01PlayTestRunner_P07_9_Phase1.cs` (Manual invocation in unit tests: `hero.TickActiveCast(...)`)
   - `Assets/_Game/Editor/Prototype01PlayTestRunner_P07_9_Phase2.cs` (Manual invocation in unit tests: `hero.CastState.Tick(...)`)
3. **Production Gameplay Loop Scan**:
   - `Assets/_Game/Scripts/BattleManager.cs`: **NOT CALLED**. `BattleManager` handles monster spawn, wave progression, and turn/tick sequencing, but does not invoke `TickActiveCast` on heroes or monsters.
   - `Assets/_Game/Entities/Entity.cs`: **NOT CALLED**. `Entity` inherits from `MonoBehaviour` but does not define an `Update()` method.
   - `Assets/_Game/Entities/Hero.cs`: **NOT CALLED**. `Hero` does not define an `Update()` method that ticks cast state.
   - `Assets/_Game/Entities/Monster.cs`: **NOT CALLED**.
   - No coroutines, animators, or standalone update runners call `TickActiveCast`.

### Classification:
- **CASE A (Test code manually calls `entity.TickActiveCast(deltaTime)` or `castState.Tick(deltaTime)`)**: **EXISTS**.
- **CASE B (Unity frame -> Battle runtime tick -> `Entity.TickActiveCast(deltaTime)`)**: **DOES NOT EXIST**.
