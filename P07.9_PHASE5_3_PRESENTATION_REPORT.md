## 6. Architecture Decision

- **Single Authority Preservation:** `CastBarUI` is 100% passive. It never modifies `SkillCastState`, never sets timers or durations, and never alters cooldowns, rage, or status effects.
- **Unified Tick Mechanism:** `CastBarUI` updates its fill and text via `UpdateDisplay(deltaTime)` called during Unity's standard `Update()` loop or via `ManualUpdate()` in simulated batchmode.
- **Event-Driven Feedback:** Interrupt notifications are received reactively via `EventBus.OnSkillCastInterrupted` to switch the UI into feedback display mode.
- **Lifecycle Cleanup:** Disabling or destroying the entity, defeating/clearing the encounter, or caster death immediately hides the cast bar and clears interrupt feedback.

---

## 7. Cast Bar Implementation

- **Visual Elements:** A root container `HeroCastBar`, filled `Image` (`fillMethod = Horizontal`), and `TextMeshProUGUI` for status text.
- **Progress Behavior:** Driven by `Entity.CastProgress` (0.0 to 1.0). Progress increases strictly monotonically with elapsed time.
- **Text Format:** Displays `"CAST: [SkillName] ([Elapsed:F1]s / [Total:F1]s)"` in cyan (`#33CCFF`).
- **Completion:** Upon reaching duration, `SkillCastState` transitions to `Recovery`, `IsActive` becomes `false`, and `CastBarUI` immediately hides the bar.

---

## 8. Channel Bar Implementation

- **Visual Elements:** Reuses the unified progress bar container with purple coloration (`#D973FF`).
- **Progress Behavior:** Progress tracks `ElapsedChannelTime / ChannelDuration` from 0.0 to 1.0 across multiple ticks.
- **Text Format:** Displays `"CHANNEL: [SkillName] ([Elapsed:F1]s / [Total:F1]s)"`.
- **Tick Visual Continuity:** Intermediate damage/heal ticks occur at scheduled channel intervals without flickering, resetting, or stuttering the fill bar.

---

## 9. Interrupt Feedback Implementation

- **Feedback Text:**
  - Stun: `"SKILL CAST INTERRUPTED (STUN)"` in vivid red (`#FF4D4D`).
  - Freeze: `"SKILL CAST INTERRUPTED (FREEZE)"` in vivid red (`#FF4D4D`).
- **Display Duration:** Displays for 2.0 seconds (or until cleared by a new action/death).
- **Progress Bar Behavior on Interrupt:** Fill immediately freezes at 0%, progress fill image is disabled, and text switches to the interrupt alert.
- **Repeated Interrupt Protection:** Duplicate interrupts (e.g. repeated Stun applications) do not duplicate or corrupt text strings.

---

## 10. Instant Skill Behavior

- **CastTime == 0 / IsChannel == false:**
  - `CastBarUI` checks `SkillCastState.IsActive`. Since instant skills execute synchronously within `Execute()` and do not enter `Casting` or `Channeling` phase, `CastState.IsActive` remains `false`.
  - The Cast Bar never appears, never flashes for 1 frame, and never shows residual text. Verified in Automated TEST 01 and Play Mode Visual H.

---

## 11. Root Behavior

- **Non-Interrupting CC:**
  - Root restricts movement (`CanMove == false`), but does NOT affect action execution (`CanUseSkill == true`).
  - Applying Root during Cast Time or Channel does NOT interrupt `SkillCastState`.
  - The Cast Bar continues progressing normally to completion under Root without showing interrupt feedback. Verified in Automated TEST 07, TEST 15, and Play Mode Visual E.

---

## 12. Ordinary Damage Behavior

- **Non-Lethal Damage:**
  - Taking ordinary (non-lethal) damage does NOT interrupt skill cast or channel.
  - Cast Bar / Channel Bar fill continues progressing uninterrupted.
  - No interrupt feedback is shown. Verified in Automated TEST 08, TEST 16, TEST 22, and Play Mode Visual F.

---

## 13. Stun Behavior

- **Hard Interruption:**
  - Applying Stun immediately invokes `Entity.InterruptCurrentAction(SkillCastInterruptSource.Stun)`.
  - `SkillCastState` transitions to `Interrupted`.
  - Cast Bar stops immediately, fill resets, and `"SKILL CAST INTERRUPTED (STUN)"` feedback is displayed.
  - Cooldown is NOT consumed; rage is NOT refunded. Verified in Automated TEST 05, TEST 13, TEST 19, and Play Mode Visual C.

---

## 14. Freeze Behavior

- **Hard Interruption:**
  - Applying Freeze immediately invokes `Entity.InterruptCurrentAction(SkillCastInterruptSource.Freeze)`.
  - `SkillCastState` transitions to `Interrupted`.
  - Cast Bar stops immediately, fill resets, and `"SKILL CAST INTERRUPTED (FREEZE)"` feedback is displayed. Verified in Automated TEST 06, TEST 14, TEST 20, and Play Mode Visual D.

---

## 15. Anti-CC Behavior

- **CC Immunity:**
  - When target has active Anti-CC immunity (`ApplyAntiCCImmunity`), incoming Stun or Freeze is completely blocked (`[CC:IMMUNE]`).
  - Skill cast / channel continues uninterrupted to completion.
  - No interrupt UI is shown. Verified in Automated TEST 09.

---

## 16. Death Behavior

- **Caster Death (Non-Ghosting):**
  - When caster health reaches 0, `EventBus.OnEntityDied` fires.
  - `CastBarUI.HandleEntityDied()` immediately calls `ClearInterruptFeedback()` and `HideCastBar()`.
  - Zero ghost UI, zero frozen progress bars, and zero lingering interrupt text remain visible on screen. Verified in Automated TEST 25, TEST 26.

## 21. Architecture Safety Audit

- **No New Gameplay Authority:** `CastBarUI` is strictly read-only presentation.
- **No Rogue Timers / Coroutines:** All progression is strictly derived from `SkillCastState` ticks driven by entity update.
- **Decoupled Event Listening:** `EventBus` event subscriptions are strictly registered and unregistered in `OnEnable`/`OnDisable`/`OnDestroy` and teardowns to prevent memory leaks.
- **Defensive Null Checks:** All UI accessors verify object existence (`this == null || !gameObject`) to avoid editor lifecycle issues.

## 23. Simultaneous Stun + Freeze Status

- **Edge Case:** Stun and Freeze applied in the exact same frame or sequentially.
- **Phase 5.3 Audit Result:** **RESOLVED IN RUNTIME / PRESENTATION PASS-THROUGH**.
- **Behavior:**
  - Whichever hard CC is processed first by `EntityStatusController.ApplyCrowdControl` triggers `InterruptCurrentAction(SkillCastInterruptSource)` and sets `SkillCastState.InterruptSource`.
  - Once interrupted, `SkillCastState.IsActive` is false; subsequent CC applications in the same frame cannot interrupt an already-interrupted state.
  - In `Entity.InterruptCurrentAction()`, if called with generic `CrowdControl`, `IsStunned` precedes `IsFrozen`.
  - `CastBarUI` strictly displays the source passed from runtime authority without inventing UI-side precedence rules.
