## 2. Current Movement Architecture

Audited `MovementComponent.cs` (`Assets/_Game/Entities/Components/MovementComponent.cs`) and `Entity.cs` (`Assets/_Game/Entities/Entity.cs`):

1. **Authoritative Movement Execution Authority**:
   - `MovementComponent` is the sole runtime component responsible for calculating and updating an Entity's position on the transform (`MoveTowardTarget` and `MoveDirection`).
   - Movement execution occurs exclusively within `MovementComponent`:
     - Line 46: `ManualTick(deltaTime)` -> `MoveTowardTarget(...)`
     - Line 59: `Update()` -> `MoveTowardTarget(...)`
     - Line 75: `transform.position += moveDelta;` inside `MoveTowardTarget`
     - Line 87: `transform.position += moveDelta;` inside `MoveDirection`

2. **Authoritative Movement Permission Gate**:
   - `MovementComponent` does not make arbitrary movement decisions; it evaluates gates in this exact sequence:
     ```csharp
     if (!isMovementEnabled || ownerEntity == null || !ownerEntity.IsAlive || !ownerEntity.CanMove) return;
     ```
   - In `Entity.cs`:
     ```csharp
     public virtual bool CanMove => StatusController == null || StatusController.CanMove;
     ```
   - Therefore, `Entity.CanMove` is the overarching, centralized gate queried by all movement operations.

3. **No AI/Hero Movement Fragmentation**:
   - Neither `Hero.cs` nor `Monster.cs` contains custom movement logic or overrides `MovementComponent`.
   - `BattleManager.cs` registers entities and sets targets but performs zero direct transform updates.

## 3. Current Cast/Channel Architecture

Audited `SkillCastState.cs`, `SkillExecutor.cs`, and `Entity.cs`:

1. **Cast Lifecycle**:
   - `SkillCastState` manages lifecycle phases: `Ready = 0`, `Casting = 1`, `Channeling = 2`, `Recovery = 3`, `Interrupted = 4`.
   - `IsActive` is defined as:
     ```csharp
     public bool IsActive => CurrentPhase == SkillCastPhase.Casting || CurrentPhase == SkillCastPhase.Channeling;
     ```
2. **Entity Cast Binding**:
   - In `Entity.cs`:
     ```csharp
     public virtual bool IsCasting => CastState != null && CastState.IsActive;
     ```
3. **Runtime Progression**:
   - `Entity.Update()` ticks the active cast/channel deterministically:
     ```csharp
     protected virtual void Update()
     {
         if (BattleManager.Instance != null && !BattleManager.Instance.IsBattleActive)
             return;
         if (!IsAlive || !IsCasting)
             return;
         TickActiveCast(GetDeltaTime());
     }
     ```
   - On completion boundary, `SkillCastState.Complete()` transitions `CurrentPhase` to `Recovery`.
   - Once in `Recovery`, `IsActive` becomes `false`, and `Entity.IsCasting` immediately returns `false`.

## 4. Current CC Movement Behavior

Audited `EntityStatusController.cs` (`Assets/_Game/Combat/EntityStatusController.cs`):

1. **CC Movement Gate**:
   ```csharp
   public bool CanMove => !IsStunned && !IsRooted && !IsFrozen;
   ```
2. **Stun**:
   - Sets `IsStunned = true`.
   - `StatusController.CanMove` returns `false`.
   - Triggers `OwnerEntity.InterruptCurrentAction()`, which stops active cast/channel (Phase 4).
3. **Freeze**:
   - Sets `IsFrozen = true`.
   - `StatusController.CanMove` returns `false`.
   - Triggers `OwnerEntity.InterruptCurrentAction()`, which stops active cast/channel (Phase 4).
4. **Root**:
   - Sets `IsRooted = true`.
   - `StatusController.CanMove` returns `false`.
   - `CanUseSkill` remains `true` (`!IsStunned && !IsFrozen`).
   - Does NOT call `InterruptCurrentAction()`; active cast/channel continues unimpeded.
5. **Simultaneous Cast Lock and Root**:
   - When an entity casts a skill, movement is locked by the cast.
   - If Root is applied during the cast, Root also locks movement (`IsRooted = true`).
   - When the cast completes, casting movement lock releases, but Root remains active.
   - Because Root still sets `StatusController.CanMove = false`, the entity cannot move until Root expires.
   - Deterministic and conflict-free.

## 6. Death Behavior

Audited death flow in `HealthComponent.cs`, `SkillCastState.cs`, and `MovementComponent.cs`:

1. When an entity takes lethal damage:
   - `HealthComponent` marks `isDead = true` (`Entity.IsAlive => Health == null || Health.IsAlive`).
2. Cast interruption on death:
   - `SkillCastState.Tick()` detects `!ActiveRequest.Source.IsAlive` and executes `Interrupt(SkillCastInterruptSource.CasterDeath)`.
   - `CurrentPhase` becomes `Interrupted`, `IsCasting` becomes `false`.
3. Movement check on death:
   - `MovementComponent.Update()` and `ManualTick()` both evaluate `!ownerEntity.IsAlive` before attempting displacement:
     ```csharp
     if (!isMovementEnabled || ownerEntity == null || !ownerEntity.IsAlive || !ownerEntity.CanMove) return;
     ```
   - Movement stops immediately.
4. Revival:
   - If the entity is revived via `Health.Revive()`, `IsAlive` becomes `true`.
   - Since the interrupted cast is terminal and inactive (`IsCasting == false`), `CanMove` returns `true` (unless CC'd).
   - No permanent movement lock can linger after death.

## 7. Exact Runtime Call Chain

The complete frame update sequence in Unity is:

```
Unity Frame Update
  │
  ├─► Entity.Update()
  │     ├─ Guard: !IsAlive || !IsCasting -> early return
  │     └─ TickActiveCast(Time.deltaTime)
  │          └─ CastState.Tick(deltaTime)
  │               ├─ [During Cast]: ElapsedTime += dt
  │               ├─ [Boundary Reached]: Complete() -> CurrentPhase = Recovery -> IsCasting = false
  │               │                      ExecuteCastComplete() -> OnSkillExecutionSucceeded
  │               ├─ [During Channel]: ElapsedChannelTime += dt -> Channel ticks execute
  │               └─ [Channel End]: Complete() -> CurrentPhase = Recovery -> IsCasting = false
  │
  └─► MovementComponent.Update()
        ├─ Guard: !isMovementEnabled -> return
        ├─ Guard: ownerEntity == null -> return
        ├─ Guard: !ownerEntity.IsAlive -> return
        ├─ Guard: !ownerEntity.CanMove -> return   <-- [EVALUATES !IsCasting]
        └─ MoveTowardTarget(targetPosition, stoppingDistance, dt)
             └─ transform.position += moveDelta
```

Both components reside on the same GameObject and execute within the standard Unity update cycle without coroutines, threads, or custom tick managers.

## 8. Recommended Minimal Integration Point

The optimal, architectural integration point is in `Assets/_Game/Entities/Entity.cs`:

```csharp
public virtual bool CanMove => (StatusController == null || StatusController.CanMove) && !IsCasting;
public virtual bool CanDash => (StatusController == null || StatusController.CanDash) && !IsCasting;
```

### Why this is the optimal approach:
1. **Single Source of Truth**:
   - `Entity` is already the unified façade for all action permissions (`CanMove`, `CanBasicAttack`, `CanUseSkill`, `CanUseUltimate`, `CanDash`).
2. **Zero Pollution of CC Authority**:
   - `EntityStatusController` remains purely responsible for CC, buffs, and debuffs. It does not need to inspect `SkillCastState`.
3. **Zero Pollution of Cast Authority**:
   - `SkillCastState` remains purely responsible for cast duration and phase timing. It does not need to inspect `MovementComponent`.
4. **Zero Modification to MovementComponent**:
   - `MovementComponent` already checks `ownerEntity.CanMove` at all 4 exit/entry gates (`ManualTick`, `Update`, `MoveTowardTarget`, `MoveDirection`).
5. **Automatic Lifecycle Synchronization**:
   - When a cast starts: `IsCasting` becomes `true` -> `CanMove` returns `false` -> movement immediately stops.
   - When a cast completes: `IsCasting` becomes `false` -> `CanMove` returns `true` -> movement resumes.
   - When a cast is interrupted by Stun/Freeze: `IsCasting` becomes `false`, but `StatusController.CanMove` is `false` (due to Stun/Freeze) -> movement remains locked until CC expires, then automatically restores.
   - When Root is applied during cast: `StatusController.CanMove` is `false` -> cast completes normally -> movement remains locked until Root expires.
