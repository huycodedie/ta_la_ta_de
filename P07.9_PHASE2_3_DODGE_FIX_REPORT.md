## 2. Exact Root Cause

The root cause was located in `Assets/_Game/Combat/DamageCalculator.cs` during the standard damage resolution pipeline:

```csharp
// 1. Dodge Check
bool isDodged = Random.Range(0f, 100f) < dodgeRate;
if (isDodged)
{
    return new DamageResult(attacker, defender, atk * skillMultiplier, 0f, false, true, damageType);
}
```

In `RunPrototype07_9PlayModeAcceptanceTests()`, the test spawns a monster target via `BattleManager` using standard monster archetypes (`bm.StartBattle()`). Standard monsters have a non-zero base Dodge rate (5%).

When `skill_taiji_2_a` finished its cast time and executed its damage effect, `DamageCalculator.CalculateDamage` rolled a successful Dodge for the target monster (`isDodged = true`). Consequently:
1. `DamageResult.Damage` was evaluated as `0.0f` (`Raw=180.0, Final=0.0`).
2. `target.Health.TakeDamage(...)` deducted 0 HP.
3. Target monster HP remained equal to initial HP (`postMonsterHp == initialMonsterHp`).
4. The test fixture assertion `bool effectsExecutedAfter = (postMonsterHp < initialMonsterHp);` evaluated to `false`.

---

## 3. Why It Was Test-Fixture Non-determinism

1. **Test Intent:** The sole objective of Test 13 in `Prototype01PlayTestRunner_P07_9_Phase2_3` is to verify the P07.9 **Cast Progression & Effect Execution** lifecycle:
   - Before cast time: `IsCasting == true`, effects NOT executed, Rage consumed, Cooldown NOT started.
   - During cast time: progression ticks forward deterministically.
   - After cast time: `IsCasting == false`, effects execute, and Cooldown starts.
2. **Unintended Dependency:** The test assertion used `postMonsterHp < initialMonsterHp` as the metric that the damage effect actually executed. However, it inadvertently relied on the target monster *failing* a random Dodge roll.
3. **Precedent:** This exact pattern occurred historically in milestone P05.7.1.14 (documented in `PROJECT_MEMORY/P07_8_LOCKED.md`), where Dodge RNG caused intermittent test failures until the test fixture was hardened by setting target monster Dodge to 0.

---

## 4. Exact Fixture Hardening Method

Per Absolute Rules:
- **No gameplay modifications:** `DamageCalculator`, `SkillExecutor`, `HealthComponent`, and default monster stats remain 100% untouched.
- **No assertion weakening:** The assertion `(postMonsterHp < initialMonsterHp)` was preserved strictly as-is. Dodge was NOT accepted as successful effect execution.
- **Fixture-level hardening:** In `Assets/_Game/Editor/Prototype01PlayTestRunner_P07_9_Phase2_3.cs`, immediately after `bm.StartBattle()`, the test fixture explicitly zeroes the Dodge stat of the spawned monster target:

```csharp
// In Assets/_Game/Editor/Prototype01PlayTestRunner_P07_9_Phase2_3.cs:
bm.StartBattle();

// Harden test fixture against non-deterministic Dodge RNG per P07.9 remediation
if (bm.CurrentMonster != null)
{
    bm.CurrentMonster.Stats.SetBaseValue(StatType.Dodge, 0f);
}
```

This guarantees that damage calculation deterministically hits the target, allowing the normal damage pipeline to deduct HP and prove cast completion effect execution.
